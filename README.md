# Единая служба ИТ-поддержки

Локальная служба ИТ-поддержки для Центра образования «Приоритет». Можно зарегистрироваться по почте или телефону, войти, создать заявку, открыть её описание и увидеть текущий статус. При регистрации по телефону используйте код страны, например +7. В локальной версии принадлежность почты или номера сотруднику не проверяется.

## Первый запуск в Windows

1. Установите Node.js 24 или новее и PostgreSQL 18. Откройте папку с `package.json` в VS Code.
2. В терминале PowerShell выполните `npm.cmd ci`.
3. При работающем PostgreSQL на порту 5432 выполните `powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\setup-db.ps1`. Один раз введите пароль администратора `postgres` в локальном окне. Сценарий создаст базу `prioritet_support` и роль `prioritet_app` и запишет строку подключения в игнорируемый Git файл `.env`. Если у вас уже есть отдельная база, укажите строку подключения в параметре `DATABASE_URL` локального файла `.env`.
4. Выполните `npm.cmd start` и откройте http://127.0.0.1:3000. При запуске приложение создаёт таблицы. Для остановки нажмите Ctrl+C. При следующих запусках достаточно команды `npm.cmd start`.

Чтобы использовать другой порт приложения, задайте `PORT` в `.env`. Сервер доступен с этого компьютера. Заявки сохраняются в PostgreSQL после перезапуска. В VS Code можно запускать проект командой **Five-Server: Start** из палитры команд. После изменения серверного кода используйте **Developer: Reload Window** и снова **Five-Server: Start**.

## Данные платформы

Оба способа запуска используют PostgreSQL из `DATABASE_URL`. Аккаунты и роли находятся в `staff`, сеансы — в `sessions`, обращения и переписка — в `tickets` и `ticket_comments`. Списки для формы и очереди читаются из таблиц `categories`, `priorities`, `statuses`, `departments` и `locations`. Новый кабинет или подразделение можно ввести при подаче заявки.

При первом запуске новой версии схема обновляется внутри транзакции. Для прежних заявок появляется начальная запись с текущими значениями. Последующие изменения статуса, приоритета и назначения сохраняются в `ticket_history` и видны в карточке. Изменения справочников можно просматривать в pgAdmin в этой же базе.

## Кабинет исполнителя

В терминале проекта выполните `npm.cmd run technician -- it@example.org`, подставив свободный рабочий адрес. Команда создаёт исполнителя и один раз показывает сгенерированный пароль в терминале. Войдите с этими данными через обычную форму. Самостоятельная регистрация создаёт только аккаунты педагогов.

В очереди можно искать заявки по номеру, теме и описанию, отбирать по автору, месту, статусу, категории и приоритету. Открытые обращения старше 24 часов помечаются в списке. Пока очередь открыта, страница проверяет изменения каждые 15 секунд.

В карточке выберите исполнителя, статус и приоритет. Ответ педагогу доступен в его переписке, внутреннюю заметку видят сотрудники ИТ-службы. При одновременной правке сервер предлагает сверить свежую версию.

ТЗ, шаблоны и материалы защиты находятся на один уровень выше каталога приложения. Журнал работ хранится в документе Word в «Материалах для защиты».

## Публикация для показа

[Страница проекта на GitHub Pages](https://mweowww.github.io/prioritet-it-support/) служит входом в размещённое приложение. Сам сервер работает на Render, данные размещаются в отдельном проекте Neon PostgreSQL.

1. Создайте базу на бесплатном плане Neon. В панели проекта откройте **Connect** и скопируйте строку подключения со всеми параметрами TLS.
2. [Разверните бесплатный веб-сервис на Render](https://render.com/deploy?repo=https://github.com/mweowww/prioritet-it-support). Вставьте строку Neon в секретное поле `DATABASE_URL`. Таблицы создаются при старте.
3. После статуса **Live** откройте адрес, выданный Render, и проверьте вход. Для GitHub Pages используется ветка `main`, каталог `/docs`. Ссылку на кабинеты указывайте после проверки адреса.
4. Педагог регистрируется на опубликованном сайте. Для выдачи роли исполнителя запустите `npm run technician -- <почта>` из доверенного терминала с переменной окружения `DATABASE_URL` этой облачной базы. Полученный пароль предназначен владельцу аккаунта.

Для другого HTTPS-домена сервера задайте `PUBLIC_ORIGIN` (например, `https://support.example.org`). На Render адрес по умолчанию берётся из `RENDER_EXTERNAL_URL`. Локальные учётные записи и заявки остаются в локальной базе.
